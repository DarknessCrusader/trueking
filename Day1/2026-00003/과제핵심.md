## 🗄️ 모듈 3. Database

### 테이블 수준 최소 권한 분리 ⭐ 핵심
> **핵심**: 같은 테이블도 액션 단위로 IAM 분리 — 쓰기 전용 vs 읽기 전용

| 클라이언트 | 허용 액션 |
|---|---|
| EKS Pod | PutItem만 |
| Lambda | Query/GetItem만 |

- 조회용 Lambda가 컴프로마이즈돼도 데이터 조작 불가 → 데이터 무결성 보호

## 📦 모듈 4. Container Registry ⭐ Unicorn과 정반대 정책

### 태그 정책 비교

| 구분 | Unicorn 과제 | 이 과제 |
|---|---|---|
| 기본 정책 | Immutable(불변) | **Mutable**(재사용 가능) |
| 예외 | `latest`만 계속 갱신 가능 | `v1.0.0`, `v1.0.1` 등 **버전 태그만 불변** |

- ECR의 **Tag Mutability Exclusion Filters** 기능으로 예외 패턴 지정
- "버전 태그=배포 이력 신뢰성 보장 위해 불변, 나머지=유동적으로 덮어쓰기 허용"은 실무 절충안
- 채점 시 v1.0.0 이미지 외엔 존재 금지 → 개발 중 테스트 태그 정리 필요

## ☸️ 모듈 5. Container Orchestration

### Fully Private + 커스텀 DNS ⭐ 핵심 심화 포인트
> **핵심**: Unicorn은 "Control Plane만 비공개"였다면, 이 과제는 **엔드포인트 접근성 자체가 아예 Private**

- 클러스터 API도 워크로드도 전부 외부에서 직접 닿을 방법 없음

### 클러스터 도메인 변경
```
*.cluster.local  →  *.wsc2026.skills.local
```
- CoreDNS ConfigMap의 `kubernetes` 플러그인 설정에서 클러스터 도메인 커스터마이징
- 멀티클러스터 환경 도메인 충돌 회피 또는 조직 표준 네이밍 적용 시 실무에서 쓰이는 기법

### IAM Role — Administrator 대신 최소 권한
> **핵심**: 관리형 서비스라도 기본 광범위 정책 그대로 쓰지 말고 커스텀 정책 작성

## 🚀 모듈 6. Deployment — 고가용성 3종 세트

| 메커니즘 | 목적 |
|---|---|
| **Topology Spread Constraints** (또는 Anti-Affinity) | Pod 2대 이상을 AZ 간 균등 분산 |
| **PodDisruptionBudget(PDB)** | 노드 드레인/업그레이드 시에도 `minAvailable: 1` 보장 |
| **Service Internal Traffic Policy: Local** (또는 Topology Aware Hints) | 동일 AZ 우선 라우팅 → Cross-AZ 트래픽 비용 절감 |

> PDB가 없으면 노드 업그레이드 중 모든 Pod가 동시에 내려갈 수 있음 — 이게 PDB의 존재 이유

### `wsc2026-static-<임의4자리>-<비번호>-bucket`
> **핵심**: 임의 문자열 = 전역 유일성 확보용 (대회장 간 충돌 방지)

## 📊 모듈 9. Observability — Alertmanager까지 포함 ⭐ Unicorn 대비 심화

### 관측(Observe) vs 대응(Alert)의 역할 분리
> **핵심**: Prometheus는 지표 수집+룰 평가, Alertmanager는 라우팅/그룹핑/실제 발송

- Unicorn 과제는 Grafana 대시보드만 요구 → 이 과제는 **Alertmanager 능동 알림 체계까지** 요구
- Grafana Threshold 설정: CPU 80%↑=빨강, 60~80%=노랑, 60%↓=초록 — 정확한 임계치 지정 필요
- 로그는 구조화 JSON(`{"level":"INFO",...}`) → Fluent Bit이 파싱 → CloudWatch Logs Insights 데이터소스로 Grafana에서 레벨별 필터링 가능

## 🌍 모듈 10. Load Balancer / CDN

### "잘못된 경로는 403"
> **핵심**: 정의 안 된 경로는 명시적으로 거부하는 화이트리스트 방식

- ALB Listener Rule의 **Default Action(고정 응답)**으로 구현

### CloudFront 3-Origin 라우팅
> **핵심**: 하나의 도메인 뒤에 여러 백엔드를 경로 기반으로 붙이는 경량 BFF 구조

| Origin | 경로 |
|---|---|
| S3 정적 | 루트 |
| ALB | `/booking` |
| Lambda | `/v1/book` |

- **캐싱은 S3만 ON, ALB/Lambda는 OFF** — 동적 API 응답을 캐싱하면 사용자마다 다른 결과가 섞이는 버그 발생
